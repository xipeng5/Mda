## 二、15 秒极简版（信息流 / 投流用）

> "IDA 强在单文件深挖，没人否认。
> 但多个 so 之间的调用关系，它一直别扭。
> MDA 把多个 so 塞进同一个会话，跨 so 调用链自动连；
> 内置 82 个 MCP 工具，AI 自己下断点、读寄存器。
> 缺点也直说：只支持 ARM64，伪代码不是真反编译。
> 单文件靠 IDA，多模块和真机验证交给 MDA。"

## 四、事实核对表（每条说法的出处）

写文案时最容易吹过头，下表是每个能上镜的说法和它的依据：

| 文案里的说法 | 依据（本仓库） | 是否可放心讲 |
|---|---|---|
| 内置 82 个 MCP 工具 | `mcp_server/tools.py` 中 `@server.tool` 共 82 处 | ✅ |
| 多 so 同会话、跨 so 调用链 | `core/session.py` 的 `_export_index` + `call_chain()` 跨 so 递归 | ✅ |
| PLT → 导入符号 → 目标导出函数 | `core/session.py` 顶部设计说明原文 | ✅ |
| 静态与动态共享同一 Session | `mcp_server/tools.py`：`_session = Session()` 单例，GUI 与 MCP 共用 | ✅ |
| 命中现场折回静态函数 | `hit_analysis` / `locate_runtime_addr` 工具 | ✅ |
| 只支持 ARM64 | `core/disasm.py`：`if so.arch != 183: raise ValueError("暂仅支持 ARM64")` | ✅（必须讲，是硬边界） |
| 伪代码是结构化的、不是真反编译 | `core/pseudocode.py` 首段原文自述 | ✅（必须讲） |
| 没有数据库持久化 | 全仓库无 `.idb`/`.i64`/session 落盘实现 | ✅（必须讲） |
| Java 层 hook | `dyn/java_bridge.py` + 5 个 `java_*` 工具 | ✅ |

**不能讲的话（会翻车）**

- ❌ "反编译比 IDA 强" —— 不是真反编译，没有 F5 同等能力
- ❌ "支持全平台/全架构" —— 只有 ARM64
- ❌ "能替代 IDA" —— 老实说替代不了
- ❌ "能改 so / patch 二进制" —— 当前无 patch 写回能力

## 五、拍摄提示

1. **前 3 秒不要出现 logo**，用观众听得懂的痛点开场（"IDA 不是唯一答案"）。
2. 讲到"多个 so 之间的调用关系"时，**语速放慢半拍**——这是全片唯一的记忆点。
3. 讲到"只支持 ARM64 / 不是真反编译"时，**不要心虚**。主动说缺点反而增加可信度，也避免专业观众在评论区拆台。
4. 背景图切换跟着口播节拍走，**每换一个概念换一张图**，不要长时间定格同一张。
5. 结尾那句"工具没有高下，只有配不配你的活"，**留 1 秒空白**再说，比连着说更抓人。
