# 16 - MCP 调用控制台（终端式输入/输出面板）

> 需求来源：2026-11-19 用户提出——
> "需要 UI 顶部建立一个界面，hook 的时候我能看到输入和输出的结果，
> 就像在终端我手动输入看结果一样"
>
> 澄清后的准确含义（用户原话）：
> "入参指的是 AI 通过 mcp 的工具调用，他往工具写的参数就是输入参，
> 结果就像终端一样打印就行了，并同时支持用户手动写 frida 命令。"

> ## ⚠️ 最终定性（2026-11-19，用户纠正三次后才确定，以此为准）
>
> 用户原话："这里就是 ai 调用 frida 执行脚本的输出啊，你没运行过 frida 脚本吗？"
> "脚本打印什么就显示什么"。
>
> **这个区域是 frida 输出终端，不是工具调用 JSON 查看器。**
> - 屏幕上逐行显示脚本 `console.log()` / `send()` 打印的文本，像 frida 命令行。
> - **不显示** MCP 工具调用的参数/返回值 JSON（preflight 那种根本不是脚本输出，
>   之前塞进去是方向性错误）。
> - 没有"输入/输出"区块、没有 JSON 格式化、没有折叠按钮。
>
> 这个定性**推翻本文档下面所有关于"AI 调用输入/输出展示"的设计**——
> 那些是走过又废弃的弯路，仅作为教训保留。
>
> **补充（2026-11-19）**：用户进一步要求"AI 通过 mcp 工具调用 frida 脚本能力时，
> 输出也要到这里"。已实现：全局 hook 包装 `frida.core.Session.create_script`，
> 所有工具内部脚本的 `send` 自动旁路到终端，带 `[工具名]` 来源标注。
> 大对象摘要化（数组 N 项预览），避免 550 个模块这种输出刷爆屏幕；
> 高频输出限流（20 行/秒）并提示省略数。

---

## 1. 要解决的三个问题

| # | 现状 | 问题 |
|---|---|---|
| 1 | `logged` 装饰器只广播 `summary`，参数被 `[:60]` 截断 | 看不到 AI 真正传了什么完整参数 |
| 2 | **工具返回值从头到尾没有上流到界面** | "输出"是空白，这是最根本的缺口 |
| 3 | 没有任何手动执行 frida 的入口 | 用户想临时跑一条命令只能去求 AI |

## 2. 形态：主视图区的一个 tab（不是弹窗）

> **重要变更（2026-11-19）**：最初做成了全屏浮层（modal），
> 用户明确纠正："工具 137 右边直接新建一个 tab 就行了，不用弹窗。"
> 现形态如下。

```
┌─ 主视图 tab 栏 ───────────────────────────────────────────┐

  ╔══════════════════════════════════════════════════════╗
  ║ 控制台  AI 调用的输入/输出 · 手动 frida              ║

  ║   输出（300 字符）                                   ║
  ║   │{ "adb": { "ok": true, "path": "/opt/homebrew/…   ║
  ║   └ 展开剩余 7 行                                    ║
  ║                                                      ║
```

**为什么用 tab 不用弹窗**：弹窗会挡住反汇编/监控台，用户要在
"看代码"和"看调用"之间反复开关，成本高。tab 与既有视图同级，
左栏导航、右栏检视器、底部状态栏全部保留，可以随手并排切。


## 3. 关键设计决策（含理由）

### 3.1 result 必须截断，且必须如实标注

`hits()` 单条命中约 12KB，`disassemble` 可能几万行。前端直接渲染会卡死浏览器。
策略：
- 单条 result 上限 `32KB`，超出截断并标 `truncated: true` + 原始长度
- 前端默认折叠长结果（超过 30 行折叠，点击展开）
- **绝不静默截断**：界面上必须显示"已截断，原长 N 字节"

### 3.2 `_activity_log` 必须加上界

原实现是**无界 list**（`_activity_log: list[dict] = []`）。加 result 之前，
每条记录只有几字节的 summary；加之后每条可能 32KB，几百条就爆。
改为 `deque(maxlen=300)`，与前端保留条数一致。

### 3.3 手动 frida 执行要区分「一次性」与「常驻」

- **一次性**：`script.load()` → 等 payload → `script.unload()`（复用
  `tools._run_frida_script` 的做法）。适合 `Process.enumerateModules()` 这类主动查询。
- **常驻**：脚本里有 `Interceptor.attach` / `recv` 时不能立刻 unload。
  保持脚本存活，后续 `send()` 的消息继续推到同一条控制台流。
  需要一个 `stop` 动作来 `unload`。

判定方式**不能靠猜脚本内容**（正则匹配 `Interceptor.attach` 是不可靠的特调式写法）。
改为让用户/调用方显式选 `mode`：`once`（默认）/ `keep`。

### 3.4 屏幕上永远只有**最近一次**运行结果（真终端语义）

这一条被用户纠正了两次，最终形态是三版迭代的结果：

| 版本 | 做法 | 用户反馈 |
|---|---|---|
| v1 | 全部塞进 `events[]` 累积列表 | "frida 脚本大多数是一次性的，搞成列表干什么？" |
| v2 | 手动改单条替换，**但 AI 记录仍在累积** | "我不是说了？只要类似于控制台的那种，你给我多个运行结果是什么意思？"（截图里两条一模一样的 `preflight`） |
| **v3（最终）** | **整个显示区收敛成单个 `current` 卡片**，AI 调用/手动脚本都覆盖它 | 符合"类似控制台"的字面含义 |

**核心理解**：用户说"类似控制台"就是字面意思 ——
真终端的默认行为是**新输出把旧输出顶掉**，屏幕上只有最近一次。
我前后两次都只改了一半（先只改手动、再只改 AI），这是理解偏差的根源。

最终数据结构：

| 状态 | 含义 | 行为 |
|---|---|---|
| `current: Current \| null` | 屏幕上唯一的运行结果卡片 | AI 调用来了 → 覆盖；手动脚本执行 → 覆盖 |
| `keepLines: ApiConsoleEvent[]` | 常驻脚本的持续输出 | 唯一允许多条的场景，限 `KEEP_MAX = 10` 条紧凑显示 |

- 删掉「全部 / AI 调用 / 手动」筛选按钮 —— 只剩一条时筛选毫无意义。
- `current.kind === "manual"` 时带**脚本源码回显**：终端里命令和输出天然成对，
  只给一团 JSON，过一会儿就不知道对应哪段代码了。
- 常驻输出用 `keepIds`（常驻中的 script_id 集合）从轮询事件里分流，
  一次性脚本的 id 从不入集合 —— 避免同一次执行显示两遍。
- 「清空」按钮清掉屏幕内容与常驻输出，但**不影响正在运行的常驻脚本**。

### 3.5 手动执行必须显式指定目标

不允许"用最近那个 pid"这类隐式兜底——那会在多目标场景下把代码注到错误的进程里。
`serial` 与 `pid` 都是必填，缺了直接报错。

### 3.6 安全边界

`run_frida_js` 是在目标进程里执行任意 frida 脚本。这是**本机已授权能力**
（用户已 root、已装 frida-server、mda 本身就有 `run_script` / `run_idc` 这类等价通道），
不是新增的攻击面。但必须：
- 脚本执行错误完整回传（含 frida 给出的 `description` + `stack`）
- 不静默吞异常
- 超时如实报告（"等待 N 秒无 send 载荷" ≠ "执行成功"）

## 4. 数据流

```
AI 调工具
   ↓
logged 装饰器
   ├─ _activity(tool, args, summary, ms, result)   ← 新增 result 参数
   │     ↓
   │  _log_listeners 回调（api.py 的 _on_ai）
   │     ↓
   │  _broadcast_sync({type:"ai", args, result, ...})
   │     ↓
   │  WebSocket /api/events
   │     ↓
   │  App.tsx 的 aiEvents 状态
   │     ↓
   │  ConsoleOverlay 渲染（新增）
   │
用户手动敲 frida
   ↓
POST /api/frida_js  {serial, pid, js, mode}
   ↓
server/dyn/console.py 执行
   ↓
返回 {ok, payload|error, ms}
   ↓
前端直接 append 一条记录（同时进 aiEvents 流，保持一致）
```

## 6. 验收标准

1. AI 调任意 MCP 工具 → 控制台立刻出现一条记录，**输入显示完整参数**（不截断到 60 字符）
2. 同一条记录里**能看到返回结果**（此前完全没有）
3. 手动敲 `Process.enumerateModules().slice(0,3).map(m=>m.name)` → 能看到真实模块名
4. 手动敲 `var n=0; Interceptor.attach(ptr("0x..."),{onEnter(){send({n:++n})}})` 用 `keep` 模式
   → 命中后控制台持续刷出记录，直到点"停止"
5. 超长结果（如 `hits` 全量）**如实标注截断**，不静默丢弃
6. 脚本报错时显示 frida 的真实错误（不是"执行失败"四个字）
7. 打包后 `web/dist` 生效（需 `pnpm/npm run build`）
